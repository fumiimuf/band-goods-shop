# アプリケーション名：バンドグッズ ECサイト

## 概要・作成背景

**【概要】**  
バンドの公式グッズを購入・管理できるWebアプリケーションです。
一般ユーザーがストレスなく買い物できるEC機能と、管理者がスムーズに情報を扱えるバックオフィス機能を備えています。





【ここに動画を表示する】

**【作成背景】**  
私自身、音楽やライブ鑑賞が好きでよく会場に足を運んでいました。しかし、遠方の会場限定で魅力的なグッズが販売された際、「現地に行けないため購入すらできない」という歯がゆい経験をしてきました。

この経験から、「ユーザー登録さえしておけば、遠方に住んでいて会場に行けないファンでも、いつでも・どこでも・どのデバイス（スマホ・タブレット・PC）からでも会場限定グッズを購入できる場所を作りたい」と考え、本アプリの開発を開始しました。

## 主な機能一覧

**【一般ユーザー機能】**  
- 会員登録・ログイン・マイページ（基本情報の確認・更新）
- 商品閲覧（一覧表示・商品名検索）
- カート機能（グッズの追加および数量変更、グッズの個別削除と全削除）

**【管理者機能】**  
- 管理（グッズ登録・更新）
- 商品ステータス（販売中/停止中）切替
- 各種検索・履歴閲覧（商品名検索、ユーザー検索、販売履歴検索）


## こだわったポイント・工夫した点

**1. 快適なユーザー体験（UI/UX）と Ajax 非同期通信**  
- **ポップオーバーによる商品詳細プレビュー**  
  グッズ一覧画面から別ページへ移動することなく、その場で商品の詳細情報を確認できるポップオーバー機能を導入し、スピーディーな商品閲覧を実現しました。

- **画面遷移のないカート操作**  
  カート追加・数量変更時は Ajax 通信（非同期処理）を活用し、ページ全体の再読み込みなしで「トースト通知」と「ヘッダーのカート合計数」をリアルタイムに反映できるように構築しました。

- **スムーズな購入フロー**  
  リピート購入が多いファン層がターゲットとなっています。ユーザー登録制にすることで配送先入力の手間を省き、スムーズに手続きを完了できるようにしました。

**2. 効率的なバックオフィス・管理者機能**  
- **ワンタップでのステータス管理**  
  グッズの「販売中」「停止中」のステータスをボタン1つで素早く切替・視覚的に判別できる仕組みを導入しました。

- **情報検索**  
  登録されているグッズ情報や一般ユーザー情報をキーワードで即座に絞り込める検索機能を備え、管理業務の効率化を図りました。

**3. 堅牢なエラーハンドリングとセキュリティ（Spring Security）**  
- ユーザーに優しいリダイレクト制御  
  存在しないURL、権限外（管理者専用）ページ、不正なIDパラメータに直接アクセスされた場合でも、不快なエラー画面を出さずに安全に適切なページへリダイレクトし、トースト通知で理由を知らせる設計にしました。

- セキュリティ対策  
  ログイン認証およびユーザー/管理者別の権限に応じたアクセス制限やCSRF対策を行いました。

**4. 設計の標準化と保守性の追求**  
- バックエンドの明確なレイヤー分離  
  Controller ➔ Service ➔ Repositoryによる層状の責務分離を適用し、保守性・拡張性を確保しました。

- フロントエンドのコード統一  
  Bootstrap 5 の標準クラスのみを使用し、独自の CSS に頼らないシンプルで可読性の高い HTML 構造を追求しました。


## 開発で苦労した点と解決策

**データベースとアプリケーション（Java）における処理責務の最適化**  
- **課題と原因**  
  初期の実装では、システム全体の設計において「データベース（データの保持・抽出・集計）」と「アプリケーション（ビジネスロジック）」の役割分担があやふやなまま開発を進めていました。そのため、本来データベース側で行うべきデータ処理まで Java（Service層）側に持たせてしまい、大量データの取得に伴うメモリ消費や、不要なデータ通信によるパフォーマンス低下が課題となりました。

- **解決策と改善結果**  
  データ抽出時のフィルタリングや集計処理はデータベース側へ集約し、Java 側は純粋なビジネスロジックの実行に専念させるよう、処理の責務を切り分けました。データ層とアプリケーション層の役割を明確に再設計したことで、不要な通信を削減し、システムの処理効率向上と拡張性の高いコード構造を実現しました。

## 今後の課題・挑戦したいこと

**1. 完全非同期通信のWebアプリケーション構築**  
- **現状**  
本アプリでは、JavaScript（jQuery/Ajax）を用いて「グッズ一覧でのカート追加」および「カート画面での数量変更時の小計・合計金額とヘッダーメニューのカート合計数のリアルタイム反映」を非同期通信で実装しました。

- **今後の挑戦**  
画面全体を再読み込みせずに快適に操作できる魅力を実感したため、次回作ではより多くの機能を非同期通信で処理し、スマホアプリのように画面の切り替えがスムーズなWebアプリケーションの構築に挑戦したいと考えています。

**2. Tailwind CSSを活用したデザインと画面部品（パーツ）の共通化**  
- **現状**  
本アプリでは Bootstrap 5 を活用し、統一感のあるデザインを効率的に作成しました。

- **今後の挑戦**  
デザインの自由度や、ボタンやカードなどの「画面の部品（パーツ）」を共通化して管理する作法に興味を持ったため、次回作では Tailwind CSS を導入し、より細部までこだわったデザインと管理しやすいコード作成に挑戦したいと考えています。


## 動作確認手順

**1. 動作環境・事前準備**  
- IDE（開発環境）：Pleiades Eclipse（Java フルセット版）などの Spring Tools (STS) プラグインが組み込まれた Eclipse 環境を推奨します。

- データベース：MySQLが動作している必要があります。

**2. プロジェクトの取得・インポート**  

1. GitHubからリポジトリをクローン（またはZIPダウンロード）します。
2. Eclipseを起動し、[ファイル] ➔ [インポート] ➔ [Maven] ➔ [既存の Maven プロジェクト] を選択して、本プロジェクトをインポートしてください。

**3. データベースの設定と構築**    
1. DB接続設定の変更  
`src/main/resources/application.properties` を開き、お使いのMySQL環境に合わせて以下の設定項目（ユーザー名・パスワードなど）を変更してください。  
    - `spring.datasource.username`
    - `spring.datasource.password`

2. SQLの実行（初期構築）  
`src/main/resources/` 直下の SQL ファイルを以下の順で実行し、データベースを構築してください。
    - `schema.sql`：スキーマおよび各種テーブルの作成
    - `data.sql`：動作確認に必要な初期データの投入

**4. テスト用ログインアカウント**  
アプリケーション起動後、URL（`http://localhost:8080/login`）を入力してログイン画面へ。
以下のアカウントでログイン可能です。

- **パスワード：** `password`（共通）  

**【管理者】**  
- **メールアドレス：** `admin@example.com`
- **パスワード：** `password`

### 画像ファイル・動作に関する補足仕様

**【商品画像フォルダの用途】**  
- **商品画像保存場所：** `src/main/resources/static/images/product`  
  ※本アプリで表示・保存されるすべての商品画像が配置されるフォルダです。  
  　このフォルダ内に初期データとして既に画像が保存されています。  

- **テスト用アップロード画像：** `src/main/resources/static/images/test`  
  ※管理画面から新規商品登録・画像更新を行う際の検証用画像としてご自由にお使いください。

**【画像登録・更新時の注意点】**  
- IDE（Eclipse）上で動作させる際、画像の保存先をプロジェクト内部（`static` ディレクトリ内）に設定している仕様上、管理画面等から画像の新規登録・更新を行った直後は、ブラウザへの反映（IDEの自動リフレッシュ）までに若干のタイムラグが発生する場合があります。
